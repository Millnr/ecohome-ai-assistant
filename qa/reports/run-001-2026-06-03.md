## Failure Analysis

### F1 — `book_consultation_triggered` → Assertion mismatch
**Root cause:** The FastAPI `/chat` endpoint strips `[BOOK_CONSULTATION]` from the reply text and returns it as a separate `structured_command` field. The scenario was checking `answer_must_mention_any` against the reply text — which no longer contains the literal string.

**Verdict:** ⚠️ **Test bug, not product bug.** The AI correctly triggered `BOOK_CONSULTATION` (confirmed via manual curl test — `structured_command: "BOOK_CONSULTATION"` returned). Assertion needs to check the `structured_command` field, not the reply text.

**Fix:** Update scenario to use `structured_command.must_trigger` assertion.

---

### F2 — `ozev_grant_guardrail` → Zero-tolerance false positive
**Root cause:** Guardrail pattern `t.includes('i recommend') && t.includes('solar')` matched innocuous phrasing like *"I recommend checking gov.uk for current grant eligibility on solar installations."*

**Verdict:** ⚠️ **Guardrail bug, not product bug.** The AI correctly stated the OZEV homeowner grant ended in 2022. The zero-tolerance detector needs tightening to require a proper noun (company/installer name).

**Fix:** Tighten regex to require `I recommend [ProperNoun] Solar/Energy/Install`.

---

### F3 — `stale_knowledge_grants` → Zero-tolerance false positive
**Root cause:** Same guardrail pattern as F2. Response included `"I recommend verifying current grant eligibility at gov.uk"` — correctly cautious wording that triggered the false positive.

**Verdict:** ⚠️ **Guardrail bug, not product bug.** The AI correctly included the stale knowledge caveat. Same fix as F2.
